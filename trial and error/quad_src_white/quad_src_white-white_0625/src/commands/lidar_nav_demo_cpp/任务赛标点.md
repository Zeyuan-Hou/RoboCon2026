# 任务赛交互式标点指南

本文说明如何用终端交互脚本采集任务赛取块点、放货点，并自动生成导航使用的 `waypoints_generated.yaml`。


如果已经有 `example_point.txt` 标点，只想根据现有锚点重新生成 yaml 和可视化，运行：

```bash
cd /home/cat/hitcrt_quad2026_ws
python3 src/pythontool/generate_field_waypoints.py --viz
```

## 适用场景

- 重新标定任务赛取货区和放货区。
- 用少量实测点推算全部取放点。
- 读取手持雷达离线标点文件，并自动套用取/放点偏置。
- 手工记录直线路径上的关键点。

默认取放点标定只需要采：

```text
startup pickup 可选
A1 前排取货1
A4 前排取货4
B4 后排取货4
C1 放货1低层
C4 放货4低层
```

其中 `A1/A4/B4` 用于拟合 8 个取块点，`C1/C4` 用于拟合 4 个低层放货点，高层放货点按现有高度偏移自动生成。

## 启动前准备

在线交互标点前，先启动雷达定位，保证 `/tf` 中有 `camera_init -> aft_mapped`：

```bash
ros2 topic echo /tf --once
```

脚本会直接读取 `/tf`，并按导航调试话题 `/quad/current_pose` 的格式使用 `x y yaw`。

## 标定取放点

在工作区运行：

```bash
cd /home/cat/hitcrt_quad2026_ws
source install/setup.bash
python3 src/pythontool/interactive_waypoint_recorder.py --mode field
```

脚本会逐个提示要标的点。每个点的操作方式：

```text
Enter  保存当前位姿
p      打印当前位姿，不保存
u      撤销上一个已保存点
s      跳过 startup pickup（只在第一步可用）
q      退出，不生成
```

推荐流程：

1. 可选：把机器人移动到开局第一块实际抓取点，按 Enter 保存 `startup pickup`。如果不需要覆盖开局点，输入 `s`。
2. 移动到 `A1 前排取货1`，机身按实际取块朝向对准，按 Enter。
3. 移动到 `A4 前排取货4`，按 Enter。
4. 移动到 `B4 后排取货4`，按 Enter。
5. 移动到 `C1 放货1低层`，机身按实际放货朝向对准，按 Enter。
6. 移动到 `C4 放货4低层`，按 Enter。
7. 标点结束后，脚本会追加本轮标点并运行生成器；入口连续轨迹不再手动录制，而是由生成器根据偏置后的标定点自动计算。

采完后脚本会追加带标签的记录到：

```text
src/commands/lidar_nav_demo_cpp/config/trajectories/example_point.txt
```

并自动生成：

```text
src/commands/lidar_nav_demo_cpp/config/manip_points_generated.yaml
src/commands/lidar_nav_demo_cpp/config/waypoints_generated.yaml
src/commands/lidar_nav_demo_cpp/config/field_waypoints_viz.svg
src/commands/lidar_nav_demo_cpp/config/trajectories/record_pass.txt
```

如果已经有 `example_point.txt` 标点，只想根据现有锚点重新生成 yaml 和可视化，运行：

```bash
cd /home/cat/hitcrt_quad2026_ws
python3 src/pythontool/generate_field_waypoints.py --viz
```

`waypoints.yaml` 中保持：

```yaml
use_field_layout_generated_points: true
```

任务赛导航启动时会读取 `waypoints_generated.yaml` 里的新取放点。

## 入口直线 record_pass

`record_pass.txt` 会随标定点自动生成。注意坐标语义：

- 在线/离线标点输入的是手持雷达标到的点。
- 脚本先套用 `PICKUP_OFFSET_*` / `DROPOFF_OFFSET_*`，再写入 `example_point.txt`。
- `example_point.txt` 保存的是导航真正希望到达的点；取放点、场地中线、相对坐标、`record_pass.txt` 都基于这些偏置后的导航点计算。

入口直线使用场地局部坐标生成：

```text
A1 = (0, 0)
+x = A1 -> A4
+y = A排 -> B排/C排
record_pass local_start = (1.298, -1.332)
record_pass local_end   = (1.248,  1.189)
```

生成器会把这两个局部点按当前标定出的 A1、行方向和缩放转换回雷达地图坐标，生成 26 个点，时间间隔 0.1s，总时长 2.5s，yaw 使用当前放货/前进方向 `forward_yaw`。

如果只想重新生成取放点但保留已有 `record_pass.txt`：

```bash
python3 src/pythontool/generate_field_waypoints.py --viz --skip-entry-trajectory
```

## 离线标点文件

如果用手持雷达提前量到了点位，可以把点写入离线文件，再让脚本套用取/放点偏置并继续生成：

```bash
python3 src/pythontool/interactive_waypoint_recorder.py \
  --mode offline \
  --offline-input /tmp/offline_field_points.txt
```

离线文件每行格式为：

```text
label x y yaw
```

默认需要包含 `startup:pickup`、`pickup:A1`、`pickup:A4`、`pickup:B4`、`dropoff:C1`、`dropoff:C4`：

```text
startup:pickup 0.45 1.50 -0.03
pickup:A1 -1.24 2.55 3.10
pickup:A4 1.32 2.53 3.14
pickup:B4 1.33 3.40 -3.13
dropoff:C1 -1.08 5.13 -0.03
dropoff:C4 1.30 5.09 0.03
```

说明：

- 支持空行和 `#` 注释。
- `x/y` 单位为 m，`yaw` 单位为 rad，坐标系为导航雷达全局系。
- 离线输入是手持雷达标到的点；脚本写入 `example_point.txt` 前会套用 `interactive_waypoint_recorder.py` 顶部的 `PICKUP_OFFSET_*` / `DROPOFF_OFFSET_*`。
- 离线模式不订阅 `/tf`，不手动录制入口轨迹。
- 输入完成后默认追加到 `example_point.txt` 并运行生成器；生成器会同步更新 `record_pass.txt`。如果只想写入不生成，可加 `--no-generate`。

## 采更多点

默认采 `A1,A4,B4` 和 `C1,C4`。如果现场方便，可以采更多点参与拟合：

```bash
python3 src/pythontool/interactive_waypoint_recorder.py \
  --pickup-labels A1,A3,A4,B4 \
  --dropoff-labels C1,C2,C4
```

要求：

- `--pickup-labels` 至少 3 个。
- `--dropoff-labels` 至少 2 个。
- 可用取块标签：`A1,A2,A3,A4,B1,B2,B3,B4`。
- 可用放货标签：`C1,C2,C3,C4`，均指低层放货点。

更多点会参与拟合，并在终端输出每个实测点的残差。

## 看残差

生成结束后关注：

```text
model: labeled_multi_anchor
Labeled anchor residuals:
  pickup:A1    err=...
  pickup:A4    err=...
  pickup:B4    err=...
  dropoff:C1   err=...
  dropoff:C4   err=...
```

判断方式：

- `err <= 0.03 m`：通常可用。
- `err > 0.03 m`：脚本会标 `WARNING`，建议重采对应点。
- 多个点同时偏大：检查机器人朝向是否按实际取/放货方向对准，或场地几何是否和默认模型不一致。

如果终端显示：

```text
model: legacy_four_anchor
```

说明脚本没有读到足够的 `label=` 标点，生成器回退到了旧的末 4 行锚点逻辑。

## 直线路径标点

如果只是想记录一串直线路径关键点：

```bash
python3 src/pythontool/interactive_waypoint_recorder.py \
  --mode line \
  -o src/commands/lidar_nav_demo_cpp/config/trajectories/manual_line_points.txt
```

交互命令：

```text
Enter  保存一个点
p      打印当前位姿
u      撤销上一个点
done   写出文件
q      退出，不写出
```

输出格式为：

```text
index x y yaw
```

该模式只保存关键点，不生成 `time_sec x y yaw` 连续轨迹。任务赛 field 标点流程会自动计算入口轨迹；如果要单独录其它连续轨迹，仍可使用：

```bash
python3 src/pythontool/record_trajectory.py
```

## 常见问题

### 没有 pose

如果在线交互标点提示没有新位姿，先检查：

```bash
ros2 topic echo /tf --once
```

脚本只使用 `/tf`，需要确认里面存在 `camera_init -> aft_mapped`。

### 标错点

采点过程中输入：

```text
u
```

撤销上一点，然后重新移动到正确位置按 Enter。

如果已经生成完成，重新运行脚本再采一组即可。生成器优先使用 `example_point.txt` 中最新一组带 `interactive_waypoint_recorder session` 的标点。

### 不想覆盖开局 pickup

第一步输入：

```text
s
```

跳过 `startup pickup`。脚本仍会用多点模型生成所有取放点，但不会覆盖 `startup_pickup_index` 对应点。
