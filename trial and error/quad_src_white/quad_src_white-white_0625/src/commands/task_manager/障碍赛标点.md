# 障碍自动标点与路径生成 README

本文说明如何使用两步式工具生成障碍赛路径：

```text
交互标关键点 -> 保存 obstacle_points.json -> 离线生成 raw/smooth 路径和可视化图
```

适用场景：

- 不想手推机器人完整录一条轨迹；
- 已经知道每个障碍希望经过的关键点；
- 需要从直线、L 型折线、蛇形控制点自动生成平滑可执行轨迹。

本流程不会修改 `obstacle_race_params.yaml`，不会覆盖正式 `traj/*.txt`。所有输出默认写到：

```text
src/commands/task_manager/traj/generated/<session>/
```

## 1. 坐标和 yaw 约定

所有标点和生成轨迹都使用当前障碍赛执行器的格式：

```text
time_sec x y yaw_rad
```

其中：

- `x/y`：雷达/建图坐标系，单位 m；
- `yaw`：雷达 yaw，单位 rad；
- 车头方向不是文件里的 yaw，换算关系是：

```text
body_heading_rad = lidar_yaw_rad + pi/2
```

也就是说，现场标点脚本保存的是雷达 yaw；生成路径和 `nav_target` 摘要也都使用雷达 yaw。

## 2. 需要标哪些点

默认障碍顺序：

```text
start_transit -> pole -> sand -> crawl -> slope -> bridge_a -> bridge_b -> stairs -> wall -> end_transit
```

点位清单：

| 槽位 | 模板 | 需要标的点 | 生成路径 |
| --- | --- | --- | --- |
| `start_transit` | transit | `start`，可跳过 | 不生成路径，只写 nav_target 摘要 |
| `pole` | spline | `start`, `control_1` ... `control_6`, `end` | 蛇形样条路径 |
| `sand` | l_shape | `start`, `corner`, `end` | 带圆角的 L 型路径 |
| `crawl` | start_only | `start` | 不生成路径，只写 nav_target 摘要 |
| `slope` | line | `start`, `end` | 直线路径 |
| `bridge_a` | line | `start`, `end` | 直线路径 |
| `bridge_b` | line | `start`, `end` | 直线路径 |
| `stairs` | line | `start`, `end` | 直线路径 |
| `wall` | start_only | `start` | 不生成路径，只写 nav_target 摘要 |
| `end_transit` | transit | `start`，可跳过 | 不生成路径，只写 nav_target 摘要 |

说明：

- `start` 通常就是该障碍的导航起点，对应 `obstacle_sequence.<slot>.nav_target`。
- `end` 是障碍内部路径终点。
- `sand.corner` 是 L 型折线拐角，生成器会按 `--corner-radius` 做圆角。
- `pole.control_*` 是机器人希望经过的蛇形路径控制点，不是杆中心点。
- 绕杆默认 6 个中间控制点，其中 L 型拐弯处需要单独设置一个控制点；如果现场需要更多或更少，可以用 `--pole-controls N`。

## 3. 绕杆四杆 L 型标定细则

当前绕杆障碍按“四根杆，L 型排布，杆间距 1m”处理。标点脚本不会让你标杆中心，而是让你标机器人中心希望经过的路径控制点：

```text
pole.start -> pole.control_1 -> ... -> pole.control_6 -> pole.end
```

生成器会用这些点生成一条蛇形样条路径，所以点位要落在机器人实际可走的位置上，不能落在杆中心或杆边缘。

### 3.1 杆编号方式

现场先按机器人通过顺序给四根杆编号：

```text
P1 -> P2 -> P3 -> P4
```

四根杆构成 L 型。可以理解为：

```text
P1 ---- 1m ---- P2 ---- 1m ---- P3
                         |
                         1m
                         |
                         P4
```

如果现场 L 型方向相反、旋转 90 度、或者镜像，不需要改脚本；仍然按实际通过顺序把它们叫做 `P1/P2/P3/P4` 即可。

### 3.2 标点原则

绕杆要标的是“车身中心轨迹”，不是杆中心。

建议间距：

```text
机器人中心到杆中心侧向距离：0.35m ~ 0.50m
起点到 P1 前方距离：0.50m ~ 0.80m
终点到 P4 后方距离：0.50m ~ 0.80m
```

如果现场机器人宽、速度高、或定位抖动明显，优先把侧向距离放大到 `0.45m ~ 0.55m`。不要为了贴近杆而把控制点放得太窄，否则 smooth 后和实际跟踪误差叠加，容易蹭杆。

### 3.3 默认 6 个控制点怎么标

默认命令会提示 8 个绕杆点：

```text
pole.start
pole.control_1
pole.control_2
pole.control_3
pole.control_4
pole.control_5
pole.control_6
pole.end
```

推荐含义如下：

| 点名 | 放置位置 | 用途 |
| --- | --- | --- |
| `pole.start` | P1 前方约 `0.5m ~ 0.8m`，对准入口方向 | 导航到绕杆入口，作为蛇形路径起点 |
| `pole.control_1` | 绕过 P1 的一侧，离 P1 中心约 `0.35m ~ 0.50m` | 第一根杆外侧切入 |
| `pole.control_2` | P1/P2 中间区域的另一侧，离两杆都留足安全距离 | 从 P1 侧切到 P2 侧，形成第一段 S |
| `pole.control_3` | P2/P3 前半段或进入 L 型拐角前的位置 | 提前把路径带入 L 型拐角 |
| `pole.control_4` | L 型拐弯处的转弯外侧，通常在 P3 拐向 P4 的圆角外侧 | 拐弯关键点，专门约束 L 型转角不要切角 |
| `pole.control_5` | P3/P4 之间或 P3 外侧，按实际绕行方向放在另一侧 | 完成拐角后的第二段 S |
| `pole.control_6` | 绕过 P4 的外侧，离 P4 中心约 `0.35m ~ 0.50m` | 最后一根杆外侧出杆 |
| `pole.end` | P4 后方约 `0.5m ~ 0.8m`，对准离开方向 | 蛇形路径终点 |

一个简单记法：

```text
start 在入口前
control 点沿着希望车身中心走过的位置依次摆
每经过一根杆，路径在杆的左右侧交替
control_4 必须放在 L 型拐弯处，专门压住拐角曲线
end 在出口后
```

### 3.4 yaw 怎么对

标点保存的是雷达 yaw，不是车头 yaw。但现场操作时可以按车头方向理解：

```text
车头朝向 = 雷达 yaw + pi/2
```

实际标点时，建议把机器人车头摆成该点附近希望前进的切线方向：

- `pole.start`：车头朝向第一段入口方向；
- 中间 `control_*`：车头沿蛇形曲线的大致切线方向；
- `pole.end`：车头朝向离开绕杆的方向。

生成器默认 `--yaw-mode tangent`，会根据路径切线生成中间 yaw，并精确保留起点和终点 yaw。因此最重要的是把 `pole.start` 和 `pole.end` 的朝向摆准；中间点 yaw 也建议摆顺，但不会像起终点那样关键。

### 3.5 现场标点步骤

只标绕杆，可以单独运行：

```bash
python3 src/pythontool/record_obstacle_points.py \
  --sequence pole \
  --pole-controls 6
```

按提示依次操作：

```text
1. 把机器人放到 P1 前方入口点，车头朝入口方向，Enter 保存 pole.start
2. 把机器人中心放到 P1 外侧绕行点，Enter 保存 pole.control_1
3. 把机器人中心放到 P1/P2 之间另一侧，Enter 保存 pole.control_2
4. 把机器人中心放到进入 L 型拐角前的位置，Enter 保存 pole.control_3
5. 把机器人中心放到 L 型拐弯处外侧关键点，Enter 保存 pole.control_4
6. 把机器人中心放到 P3/P4 段另一侧，Enter 保存 pole.control_5
7. 把机器人中心放到 P4 外侧出杆点，Enter 保存 pole.control_6
8. 把机器人放到 P4 后方出口点，车头朝出口方向，Enter 保存 pole.end
```

生成并画图：

```bash
python3 src/pythontool/generate_obstacle_paths.py \
  --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json \
  --obstacles pole \
  --spacing 0.05 \
  --dt 0.1 \
  --yaw-mode tangent \
  --viz
```

检查输出图：

```text
src/commands/task_manager/traj/generated/<session>/pole_generated_smooth_viz.png
```

图里需要确认：

- 曲线没有穿过任何杆中心；
- 每根杆的最近距离大约还有 `0.25m` 以上余量；
- L 型拐角处曲线是连续圆滑的，不是尖角；
- 起点和终点箭头方向符合入口/出口方向；
- 曲线没有明显切角，尤其是 P2/P3 附近的 L 型拐角。

### 3.6 什么时候增加控制点

如果 6 个控制点生成的曲线在 L 型拐角切角明显，或者四根杆布局较紧，建议继续增加控制点：

```bash
python3 src/pythontool/record_obstacle_points.py \
  --sequence pole \
  --pole-controls 8
```

8 个控制点时，可以把额外点放在：

```text
control_3/control_4/control_5：L 型拐角前、中、后各一个点
control_6/control_7：P3/P4 段前后各一个点
control_8：P4 外侧出杆点
```

判断标准很直接：如果图里的曲线离某根杆太近，就在那根杆附近补一个控制点，把车身中心路径“拉”到更安全的位置。

## 4. 一键启动标点

先启动机器人定位，确认 `/tf` 中有：

```text
camera_init -> aft_mapped
```

然后在工作区根目录运行：

```bash
bash -lc 'cd /home/cat/hitcrt_quad2026_ws && source /opt/ros/humble/setup.bash && source install/setup.bash && python3 src/pythontool/record_obstacle_points.py --source auto --output-root src/commands/task_manager/traj/generated'
```

交互命令：

```text
Enter  保存当前点
p      打印当前位姿
u      撤销上一个点
s      跳过可选点，目前 start_transit/end_transit 可跳过
q      退出且不写入
```

标点完成后，脚本会写入：

```text
src/commands/task_manager/traj/generated/<session>/obstacle_points.json
```

如果只想使用 TF，不想读取 `/quad/current_pose`：

```bash
python3 src/pythontool/record_obstacle_points.py --source tf
```

如果绕杆需要 8 个中间控制点：

```bash
python3 src/pythontool/record_obstacle_points.py --pole-controls 8
```

## 5. 一键生成路径

标点完成后，用生成器读取 `obstacle_points.json`：

```bash
bash -lc 'cd /home/cat/hitcrt_quad2026_ws && python3 src/pythontool/generate_obstacle_paths.py --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json --spacing 0.05 --dt 0.1 --yaw-mode tangent --viz'
```

常用参数：

| 参数 | 默认 | 作用 |
| --- | --- | --- |
| `--spacing` | `0.05` | smooth 轨迹重采样点距，单位 m |
| `--dt` | `0.1` | 输出时间步长，单位 s |
| `--yaw-mode` | `tangent` | 中间段 yaw 生成方式；起终点 yaw 会保留 |
| `--raw-step` | `0.05` | 原始几何路径采样点距，单位 m |
| `--corner-radius` | `0.25` | 沙坑 L 型拐角圆角半径，单位 m |
| `--viz` | 关闭 | 生成 png/svg 可视化图 |
| `--dry-run` | 关闭 | 只校验和打印统计，不写文件 |

先试运行、不写文件：

```bash
python3 src/pythontool/generate_obstacle_paths.py \
  --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json \
  --dry-run
```

只生成部分障碍：

```bash
python3 src/pythontool/generate_obstacle_paths.py \
  --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json \
  --obstacles pole,sand,bridge_a \
  --viz
```

## 6. 输出文件说明

生成器默认在 `obstacle_points.json` 同目录输出：

```text
src/commands/task_manager/traj/generated/<session>/
  obstacle_points.json
  nav_targets_summary.yaml
  paths_summary.txt

  pole_generated_raw.txt
  pole_generated_smooth.txt
  pole_generated_smooth_viz.png
  pole_generated_smooth_viz.svg

  sand_generated_raw.txt
  sand_generated_smooth.txt
  sand_generated_smooth_viz.png
  sand_generated_smooth_viz.svg

  slope_generated_raw.txt
  slope_generated_smooth.txt
  bridge_a_generated_smooth.txt
  bridge_b_generated_smooth.txt
  stairs_generated_smooth.txt
  ...
```

文件含义：

| 文件 | 含义 |
| --- | --- |
| `obstacle_points.json` | 标点原始记录，包含每个点的 `x/y/yaw/source/time` |
| `*_raw.txt` | 按模板生成的原始几何路径 |
| `*_smooth.txt` | 平滑、重采样、保留起终点 yaw 后的执行轨迹 |
| `*_smooth_viz.png/svg` | 路径可视化图，箭头显示车头方向 |
| `nav_targets_summary.yaml` | 可人工复制到 `obstacle_race_params.yaml` 的 `nav_target` 摘要 |
| `paths_summary.txt` | 每条路径的点数、长度、输出文件汇总 |

`*_smooth.txt` 可以作为 `path_profiles.<slot>.trajectory_file` 的候选路径。确认图和实机测试都正常后，再手动更新正式配置或复制到正式 `traj/` 文件。

## 7. 推荐现场流程

```text
1. 启动雷达定位和基础 ROS 环境。
2. 运行 record_obstacle_points.py。
3. 按提示把机器人放到每个关键点，Enter 保存。
4. 运行 generate_obstacle_paths.py --dry-run，先检查点是否完整。
5. 运行 generate_obstacle_paths.py --viz，生成 smooth 轨迹和图。
6. 打开 *_smooth_viz.png/svg 检查路径、起点、终点、车头方向。
7. 从 nav_targets_summary.yaml 复制 nav_target。
8. 把确认过的 *_smooth.txt 填入或复制到对应 path_profiles。
9. 启动障碍赛低速测试。
```

## 8. 确认路径后如何应用

确认 `*_smooth_viz.png/svg` 里的路径、起终点和车头方向都正确后，用应用脚本把生成结果发布到正式障碍赛配置。

默认只检查，不写任何文件：

```bash
python3 src/pythontool/apply_obstacle_generated_config.py \
  --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json
```

检查通过后正式应用：

```bash
python3 src/pythontool/apply_obstacle_generated_config.py \
  --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json \
  --apply
```

只应用某一个障碍，例如绕杆：

```bash
python3 src/pythontool/apply_obstacle_generated_config.py \
  --points src/commands/task_manager/traj/generated/<session>/obstacle_points.json \
  --obstacles pole \
  --apply
```

脚本会做这些事：

```text
1. 检查 obstacle_points.json 的 schema、yaw 口径和 start/end 点。
2. 检查 *_generated_smooth.txt 是否存在、四列格式是否正确、时间是否递增。
3. 检查 smooth 轨迹起终点是否和标点 JSON 基本一致。
4. 备份 obstacle_race_params.yaml。
5. 备份即将覆盖的正式轨迹 txt。
6. 复制 generated smooth 到正式 traj 文件。
7. 更新 obstacle_sequence.<slot>.nav_target。
8. 更新 path_profiles.<slot>.trajectory_file。
9. 写 apply_report_<timestamp>.txt。
```

正式路径发布映射：

| 槽位 | generated 文件 | 正式文件 |
| --- | --- | --- |
| `pole` | `pole_generated_smooth.txt` | `traj/pole_final.txt` |
| `sand` | `sand_generated_smooth.txt` | `traj/sand_final.txt` |
| `slope` | `slope_generated_smooth.txt` | `traj/slope_final.txt` |
| `bridge_a` | `bridge_a_generated_smooth.txt` | `traj/bridge_a_final.txt` |
| `bridge_b` | `bridge_b_generated_smooth.txt` | `traj/bridge_b_final.txt` |
| `stairs` | `stairs_generated_smooth.txt` | `traj/stairs_final.txt` |

`crawl`、`wall`、`start_transit`、`end_transit` 没有路径文件，只更新或检查 `nav_target`。

应用后会生成报告：

```text
src/commands/task_manager/traj/generated/<session>/apply_report_<timestamp>.txt
```

报告里会记录：

```text
config_backup
nav_target_updates
trajectory_publications
trajectory_file_updates
```

回滚方式：

```text
1. 用报告里的 config_backup 覆盖回 obstacle_race_params.yaml。
2. 用报告里每条 trajectory 的 backup 覆盖回正式 traj 文件。
```

应用后启动节点，再用 ROS 参数确认：

```bash
ros2 param get /quad/task_executor_node path_profiles.pole.trajectory_file
ros2 param get /quad/task_manager_node obstacle_sequence.pole.nav_target
```

如果只想检查某个 session 是否能应用，但不想写文件，保持不加 `--apply` 即可。这个 dry-run 是现场推荐的第一步。

## 9. 常见问题

### 没有新鲜位姿

检查：

```bash
ros2 topic echo /tf
ros2 topic echo /quad/current_pose
```

如果 `/quad/current_pose` 没有，但 `/tf` 有 `camera_init -> aft_mapped`，用：

```bash
python3 src/pythontool/record_obstacle_points.py --source tf
```

### 图里箭头方向看起来差 90 度

这是正常的口径差异。轨迹文件保存雷达 yaw；图里箭头显示车头方向：

```text
body_heading_rad = lidar_yaw_rad + pi/2
```

如果实机车头方向确实不对，优先检查现场保存点时机器人的朝向，而不是把轨迹文件中的 yaw 当成车头 yaw。

### 沙坑 L 型拐角太急或切角太大

调 `--corner-radius`：

```bash
--corner-radius 0.15   # 更贴近拐角
--corner-radius 0.35   # 更圆滑
```

### 绕杆曲线不够贴合

增加或调整 `pole.control_*` 控制点。重新标点时可用：

```bash
python3 src/pythontool/record_obstacle_points.py --pole-controls 8
```

### 不想生成图

去掉 `--viz` 即可。之后也可以单独画图：

```bash
python3 src/pythontool/plot_trajectory.py \
  src/commands/task_manager/traj/generated/<session>/pole_generated_smooth.txt
```
