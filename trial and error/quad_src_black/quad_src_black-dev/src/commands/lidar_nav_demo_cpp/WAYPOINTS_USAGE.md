# 取货点与动态路径优先级控制使用说明

本系统支持基于外部下发的“优先级”话题，动态规划多目标取货和放货路线。

本指南将说明如何配置预设航点（waypoints.yaml），以及如何通过 `/quad/material_priorities` 话题来打乱、控制机器人的拿取顺序。

---

## 1. 理解坐标点映射与索引 (Index) 规则

在 `config/waypoints.yaml` 中，定义了 `pickup_points` 和 `dropoff_points`。
其中 `pickup_points` 每 4 个数字为一组：`[x, y, yaw, is_front]`。
节点加载参数时，会按**从上往下、从左往右**的严格顺序，为每一个组分配一个从 **0 开始的索引 (Index)**。

以包含 8 个取货点的 YAML 配置为例：
```yaml
pickup_points: [
  # 前排四个取货点
  -1.2,  1.65, 0.0, 1.0,   # -> Index 0 （一号点）
  -0.35, 1.65, 0.0, 1.0,   # -> Index 1 （二号点）
  0.57,  1.65, 0.0, 1.0,   # -> Index 2 （三号点）
  1.4,   1.65, 0.0, 1.0,   # -> Index 3 （四号点）

  # 后排四个取货点
  -1.2,  3.40, -3.15, 0.0, # -> Index 4 （五号点）
  -0.30, 3.30, -3.15, 0.0, # -> Index 5 （六号点）
  0.63,  3.30, -3.15, 0.0, # -> Index 6 （七号点）
  1.45,  3.20, -3.15, 0.0  # -> Index 7 （八号点）
]
```

同样地，`dropoff_points` (每 3 个数字一组) 也对应相同的索引（0 到 7），代表着放货的坑位顺序。

---

## 2. 优先级下发与排序规则

节点启动后会挂起，等待收到来自外部的话题 `/quad/material_priorities`（类型 `std_msgs/msg/Int32MultiArray`）才会生成实际路线。

* **数组长度**：下发的优先级数组长度，必须等于或者大于 YAML 中配置的有效取货点数量（比如上面有 8 个点，数组必须至少有 8 个数字）。
* **排序规则**：数组中第 `i` 个位置的值，代表 Index 为 `i` 的物资点的优先级。**数值越大，优先级越高，越先去拿**。如果两个数值一样，则 Index 小的先拿。

### 📝 场景举例

假设有 8 个点（Index: 0~7），我们只想让机器人先拿后排的“八号点”(Index=7)，再拿前排的“一号点”(Index=0)，剩下的点最后再随便拿。

你需要发布的数组就是把第 7 个元素（八号点）设为最高值，第 0 个元素设为次高值，其他设为较低值（比如0）。

对应的终端发布命令：
```bash
#                                  Index: 0   1  2  3  4  5  6   7
ros2 topic pub /quad/material_priorities std_msgs/msg/Int32MultiArray "{data: [50, 0, 0, 0, 0, 0, 0, 100]}" -1
```

**机器人生成路线后的行为：**
1. **第一次循环**：发现 Index=7 (八号点) 的优先级最高 (100)。
   * 判断在后排 -> 从启动区驶向中间过渡点 -> 后排过渡点
   * 到达 Index=7 取货点进行取货。
   * 从后排过渡点进入放货区。
   * **放置**：将这个最高优先级的物品，放在 **放货区第 1 个坑位** (`dropoff_points` 的 Index=0)。
2. **第二次循环**：发现 Index=0 (一号点) 的优先级第二高 (50)。
   * 判断在前排 -> 驶向后排过渡点退出 -> 中间过渡点 -> 前排过渡点
   * 到达 Index=0 取货点进行取货。
   * 从前排过渡点退出 -> 中间过渡点 -> 后排过渡点。
   * **放置**：将这个物品，放在 **放货区第 2 个坑位** (`dropoff_points` 的 Index=1)。
3. 依次继续处理剩下的优先级为 0 的点。

## 3. 只想拿部分物资怎么办？

当前节点逻辑会遍历**所有配置在 YAML 里的点**。如果你只想去两个点（例如八号点和一号点），其他 6 个点**彻底不去**，有两种方案：

* **方案 A (推荐，改配置)**：
  直接在 `config/waypoints.yaml` 里把不需要拿的 `pickup_points` 和对应的 `dropoff_points` 注释掉，只保留你需要拿的两个点。然后重启节点。
* **方案 B (改代码逻辑)**：
  如果需求是“必须读取 8 个点，但可以根据优先级数值（如设定为负数或0）来判断是否直接跳过不去拿”，则需要在 `lidar_nav_demo_node.cpp` 的 `generate_path` 方法里，加入一个“优先级低于阈值就 `continue` 跳过”的判断逻辑。当前代码是无论优先级多低都会排序后遍历完的。
